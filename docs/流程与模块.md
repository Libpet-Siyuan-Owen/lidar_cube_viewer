# 单包和三包代码流程

## 从一台机器的六个包到两份外参

一台机器使用一个数据目录。以 `data/vehicle_001/` 为例，前、左、顶（FLT）和前、右、顶（FRT）各采三个摆位。先为六个包分别保存单包报告，再按雷达组合执行两次三包联合拟合。两组各自输出一份包含前、侧、顶雷达的安装外参，前雷达始终锁定。

| 步骤 | 在查看器中的操作 | 对应代码与数据去向 |
|---|---|---|
| 1. 准备单包 | 选 bag，建立或加载独立静态地图，确认 XYZ ROI | `Viewer.build_map` 调用 `front_map_builder.build_static_map`，在每个雷达自己的坐标系累计。地图存入包内 `map时间戳/`。`Viewer.confirm_roi` 用裁剪后的地图预览所选范围。 |
| 2. 用当前外参累计 | 勾选前雷达和参与标定的其他雷达，选 `/tf_static` 或 YAML，设置累计帧数 | `lidar_cube_core.accumulate` 读取勾选的原始话题，将每帧点变换到前雷达坐标系，再裁剪 ROI 并按雷达分别保存点云。帧数为 0 表示全部。包内 `Cube_Viewer_config.yaml` 保存 ROI 和参数。 |
| 3. 滤波、提面与匹配 | 可先执行滤波，再点“执行平面拟合和匹配” | `filter_points` 做体素降采样和邻域滤波。`Viewer.plane_worker` 用 `extract_planes` 对每台雷达提面，再调用 `evaluate_metrics` 对当前外参做两两匹配。未应用滤波时直接使用累计点云。 |
| 4. 保存单包结果 | 点“修正并保存外参指标” | `Viewer.save_validation` 计算候选修正。三雷达情况下利用三组配对约束，固定前雷达并复验最终关系。`result_report时间戳/` 保存内点、对应关系、评估报告和日志。通过相应校验时生成 `suggested_extrinsics.yaml`。 |
| 5. 三个摆位联合求解 | 在“三标定包联合拟合”中按顺序选择同一机器、同一组三雷达的三个包及各自的单包报告 | `lidar_cube_joint.prepare` 核对雷达、安装基准、平面和对应关系。`fit_joint` 为每个摆位建一个正交三面体，三个摆位共享侧、顶雷达的安装修正，通过各面等权的稳健点面误差求解。 |
| 6. 回代验证和历史查看 | 将“结果保存位置”设为机器目录，开始联合拟合；查看历史时加载 `joint_fit_config.yaml` | `run_joint` 将 A、B、C、N 四套外参分别应用到三个原始包。每次重新累计、滤波、提面、匹配。`JointPanel` 显示角点距离对照表及 N 相对 `/tf_static` 的安装修正。加载历史配置直接读取同目录 `validation.json`。 |

## 指标怎么读

- **单雷达拟合**看最大直角偏差（°）和最大单面拟合 RMS（mm）。前者看三面间的几何形状，后者看内点贴合各自平面的程度。
- **两台雷达匹配**看两个三面交点的距离（cm）和三个对应面的平均法向夹角（°）。
- **三摆位比较**中，每个有效单元格是一个摆位下三对雷达角点距离的平均值。只有三对都有效才显示数值；“最差情况”取同一套外参三个完整摆位中的最大值。列中使用的三个包也是联合拟合的输入包。
- **安装修正**中的位移是新旧安装原点之差的长度，转角是新旧姿态的相对旋转角。两者以 `/tf_static` 为基准。

## 查代码和找结果

| 文件 | 维护内容 |
|---|---|
| `lidar_cube_viewer.py` | 单包 GUI、配置读写、工作线程、状态与绘图、单包报告导出 |
| `front_map_builder.py` | 各雷达独立地图生成。查看器使用 `--static`，旧运动建图命令仍保留在独立脚本中 |
| `lidar_cube_core.py` | bag 和坐标变换、外参加载、ROI 累计、旧配置兼容 |
| `lidar_cube_processing.py` | 滤波、RANSAC 提面、几何指标、两两修正与单包三雷达优化 |
| `lidar_cube_correction.py` | 把单包相对修正转换为套件坐标系的安装外参，并记录最终配对复验 |
| `lidar_cube_joint.py` | 跨摆位联合求解、原始 bag 回代、联合配置与报告读写 |
| `lidar_cube_joint_panel.py` | 选包、恢复配置、运行进度和两张结果表 |

```text
data/vehicle_001/
├── static_front_top_left_…/        三个摆位各一个目录
├── static_front_top_right_…/       三个摆位各一个目录
│   ├── metadata.yaml、*.db3
│   ├── Cube_Viewer_config.yaml
│   ├── map时间戳/
│   └── result_report时间戳/
├── FLT_result_report_时间戳/
└── FRT_result_report_时间戳/
    ├── joint_fit_config.yaml       恢复包的顺序、选择的报告及两张结果表
    ├── suggested_extrinsics.yaml   联合解 N，坐标系为 sensor_kit_base_link
    ├── validation.json、metrics.log
    └── bag1_config.yaml 等         三份包配置与可用的单包外参快照
```

联合结果目录可自行指定。面板选“跟随情况1”时，结果写入第一个包目录；要得到上图的布局，选择机器目录作为结果保存位置。

## 六包四雷达

`lidar_cube_six_panel.py` 加载 FLT 和 FRT 配置。`lidar_cube_six.run_six` 读取六份单包平面内点和 ROI 快照，固定前雷达，分别为六个摆位估计靶标位姿，为左、右、顶各估计一套共享安装外参。左–右之间的关系由安装外参推算。

结果表的“左1～3”和“右1～3”按两份三包配置各自保存的顺序排列。四个候选分别回到六个原始 bag 重新累计和提面。`validation.json` 和 `metrics.log` 记录逐包、逐面及配对结果。六包解通过导出条件时生成 `suggested_extrinsics.yaml`。
